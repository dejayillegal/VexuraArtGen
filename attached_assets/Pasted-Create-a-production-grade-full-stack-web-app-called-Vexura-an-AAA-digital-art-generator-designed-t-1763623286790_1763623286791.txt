Project summary (requirements)

Text-to-Image: prompt → image

Image-to-Image: style image + prompt → image (OpenAI edits, or HF/Replicate image edit if provider supports)

Marketplace listing: secure admin endpoints (require ADMIN_API_KEY) for listing/minting placeholders (OpenSea / Phaton / Rarible). Do not store marketplace keys in repo. Provide templates & step-by-step instructions to complete listing workflows and required signatures.

Security & Production hardening: input validation, rate limiting, size limits, admin API key, CORS restrictions, helmet headers, and a scripts/rotate_keys.sh key rotation helper. Provide instructions for secret storage (Replit secrets / Vercel / AWS Secrets Manager).

Fine-tuning templates: provide bash templates for Replicate & Hugging Face (dataset format, upload steps, rough cost estimate ranges). Warn user that fine-tuning requires provider credits and may not be free.

License & compliance: include a Commercial Licensing Checklist file instructing the team to verify the model license and confirm commercial use is allowed before selling generated works. Also include recommended metadata to store license attribution in minted tokens.

CI/CD & deployment: GitHub Actions to build client, run basic tests, and deploy server to Render/Heroku and client to Vercel/Netlify. Include environment variable recommendations.

UX: professional Tailwind design, gallery view, zoom modal, animation, progress indicators (generation progress if provider supports it), and “Recent Creations” local gallery.

Delivery: produce a downloadable project ZIP once the Replit task completes.

Server: key endpoints & behavior (implement these exactly)

GET /api/ping — returns provider availability flags.

GET /api/styles — reads /vexura-client/public/styles/samples/ and returns list of {name, dataUri, thumbUri}.

POST /api/generate
Body: { prompt, provider='openai'|'hf'|'replicate', init_image?, width=512, height=512, seed?, steps?, guidance_scale? }
Behavior:

Validate inputs (express-validator). Reject sizes > 2048.

If init_image (data URI) provided: call provider’s image-edit API (OpenAI edits or HF/Replicate image2image) with prompt and init_image (pass size). If provider supports progress polling (Replicate), expose a prediction_url to client to poll progress.

If text only: call provider’s text-to-image.

Return { image: dataURI, meta: { provider, model, seed, width, height } }. Store generated images temporarily on server for batch exports if needed.

POST /api/batch_generate
Body: { prompt, sizes: ["512","1024x1024"], provider, style_image_dataUri (optional) }
Behavior:

Iterate sizes, produce images, build metadata.csv and zip them, stream zip back to client for download.

Rate limit batch to prevent abuse.

POST /api/ipfs_upload
Body: { nft_key, zip_b64 }
Behavior: upload zip to nft.storage https://api.nft.storage/upload, return JSON response (CID). Document TTL and pinning policy in README.

POST /api/marketplace/list (admin only)
Body: { title, description, image_cid, price_eth, royalties_pct, external_url }
Behavior: placeholder that validates inputs and returns structured payload to be used by caller to call marketplace API (OpenSea, Phaton). Provide detailed comments where to add provider-specific API code.

Server security & ops

Use express-rate-limit default 30 requests/min per IP; adjustable via env.

Admin endpoints must verify x-api-key header equals ADMIN_API_KEY in server .env.

Helmet headers, body size limits, and strict CORS for production host.

Log generation requests (minimal PII), rotate logs, and set retention policy (instructions in README).

Provide scripts/rotate_keys.sh to rotate ADMIN_API_KEY.

Recommend placing provider keys in Replit Secrets: OPENAI_API_KEY, HF_API_TOKEN, REPLICATE_API_TOKEN, NFT_STORAGE_KEY, ADMIN_API_KEY.

Costs: model usage has variable cost. Using OpenAI or Stability for high-resolution high-step images is billable. Use rate-limits and quotas to avoid runaway bills.
